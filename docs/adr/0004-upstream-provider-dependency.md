# 0004. Upstream Terraform provider dependency via go.mod replace

Date: 2026-05-29

## Status

Accepted

## Context

The Crossplane provider depends on
`github.com/terraform-community-providers/terraform-provider-linear`
for its Terraform resource schemas and GraphQL client. New resources
(like `linear_release_pipeline`) may exist on a fork branch before
being merged upstream.

Go modules cannot directly reference a fork when the fork's `go.mod`
declares a different module path than the import path used in the
consuming module.

## Decision

Use a `go.mod` `replace` directive to point the upstream module path
to the fork:

```
replace github.com/terraform-community-providers/terraform-provider-linear =>
    github.com/starlightromero/terraform-provider-linear v0.3.8-0.20260529181641-6a11976a6214
```

The `config/schema.json` is regenerated by building the fork's
Terraform provider binary and extracting its schema via
`terraform providers schema -json` with a dev_overrides `.terraformrc`.

Once the upstream PR is merged and a new version is tagged, the
replace directive should be removed and the dependency updated to the
released version.

## Consequences

- New Terraform resources can be tested in Crossplane before the
  upstream PR is merged
- The replace directive must be removed before releasing the Crossplane
  provider to production
- Schema regeneration requires building the Terraform provider binary
  locally (documented in `Makefile` target `generate.init`)
- The pseudo-version in the replace directive encodes the commit SHA,
  making it easy to trace which fork commit is in use
