# 0002. Manual resources outside Upjet generation

Date: 2026-05-29

## Status

Accepted

## Context

The Crossplane provider wraps the upstream
`terraform-community-providers/terraform-provider-linear` via Upjet.
Most resources are generated directly from the Terraform provider
schema. However, some resources needed by the Crossplane provider do
not exist in the upstream Terraform provider:

- **User** — an observe-only resource for looking up Linear users by
  email or ID. The upstream provider has no user data source or
  resource. Needed for cross-resource references (e.g., assigning team
  membership).

- **TeamMembership** — manages the association between a user and a
  team. The upstream provider does not expose this as a resource,
  though the Linear GraphQL API supports it via
  `teamMembershipCreate`/`teamMembershipDelete`.

## Decision

Implement these as manual (hand-written) resources that live alongside
the Upjet-generated code:

- `apis/linear/v1alpha1/user_types.go` — CRD types with kubebuilder
  markers
- `apis/linear/v1alpha1/user_managed.go` — managed resource interface
  implementation
- `internal/controller/linear/user/controller.go` — reconciler using
  the Linear GraphQL API directly

Manual resources follow the same patterns as Upjet-generated ones
(same API group, same version, same managed interface) but are not
regenerated by `go generate`. They are registered in `zz_setup.go`
via the postgen patching step.

TeamMembership is registered in the Upjet external name config
(`ExternalNameConfigs`) so it participates in the include list, but
its types file (`zz_teammembership_types.go`) is manually maintained
since it has no corresponding entry in `config/schema.json`.

## Consequences

- Manual resources must be updated by hand when the crossplane-runtime
  API changes (e.g., the v1→v2 ManagedResourceSpec migration)
- The `postgen.go` step patches `zz_setup.go` to wire in the User
  controller, since Upjet only generates setup entries for resources
  it knows about
- Adding new manual resources requires: types file, managed shim,
  controller, external name config entry, and a postgen patch to
  register the controller
- These resources should be upstreamed to the Terraform provider when
  possible to reduce maintenance burden
